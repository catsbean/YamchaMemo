# vault 형식 — 판 1

YamchaMemo가 vault(메모를 저장하는 폴더)에 무엇을 어떤 모양으로 두는지 적는다. **1.0의 약속**은 이 문서가
기준이다: 이 판에서 쓴 노트는 다음 판에서도 그대로 열린다. 형식을 바꾸면 판을 올리고, 앱이 vault를 열 때
옛 판을 새 판으로 옮기는 이전(migration)을 함께 낸다(`crates/yamcha-core/src/migrations.rs`).

> 사람이 읽는 문서다. 코드와 어긋나면 코드가 맞고 이 문서를 고친다 — 그러나 **형식을 바꾸는 코드는 이 문서와
> 판 번호를 같이 고쳐야 한다**(`HANDOFF.md` §7).

## 판 표시

`.yamcha/format.json`:

```json
{ "version": 1, "id": "3f9c…" }
```

`id`는 이 vault의 이름표다 — 처음 미러로 복제할 때 만들어 적는다. 미러 폴더가 "어느 vault의 미러인가"를 이걸로
알아본다(경로가 아니라 이름표라서 vault 폴더를 옮기거나 백업을 새 자리에 풀어도 같은 vault다). 판을 올리지 않고
덧붙인 칸이라 옛 앱은 모른 척 지나간다.

| 판 | 바뀐 것 | 이전 |
| --- | --- | --- |
| 0 | 판 표시가 생기기 전의 모든 vault | — |
| 1 | 판 표시가 생김(0.8.0). 형식 자체는 0.7.x와 같다 | 0→1: 옛 `Reading/` 폴더의 독서기록을 책의 `## 기록`으로 합친다(0.4 이전 구조). 합치기 전에 `.yamcha/migrate-backup/<시각>/`에 사본 |

vault를 열 때:
- 판 표시가 없거나 낮으면 → 그 판부터 차례대로 이전하고 판을 올린다. 이전은 두 번 돌아도 같은 결과다.
- **이 앱보다 높으면 → 열지 않는다**("이 vault는 더 새 판의 YamchaMemo에서 쓰던 것입니다"). 옛 앱이 새 형식을
  모르고 고쳐 망가뜨리지 않게. 첫 화면에서 바로 앱을 업데이트할 수 있다.
- 판 표시는 vault 안에 있어 클라우드로 이어진 다른 기기도 같은 판을 본다. 백업에 들어간다.

## 폴더

```
vault/
├── Daily/2026/09/2026-09-30.md      일지 — 연/월 폴더, 파일명이 날짜
├── Books/구운몽.md                   도서 (책 정보 + 소개 + 독서기록이 한 파일)
├── Writing/한강.md                   글쓰기(원고)
├── Free/메모.md                      자유노트
├── 회의록/…                          사용자 정의 분류 — 폴더 이름은 `_types.json`의 folder
├── _attachments/
│   ├── covers/구운몽.jpg             책 표지 (책 제목으로, 바꾸면 덮어씀)
│   └── 2026-09/그림.png              일반 첨부·붙여넣은 이미지 (달마다, 겹치면 " (2)")
├── _types.json                       사용자 정의 분류 (없으면 내장 분류만)
├── _callouts.json                    사용자 정의 기록 종류 (없으면 기본만)
├── <분류 폴더>/_index.md             앱이 만드는 목록 — 다른 편집기에서 훑어보라고. 고쳐도 다시 만든다
└── .yamcha/                          앱의 살림 (아래)
```

- **노트 = `.md` 파일 중 이름이 `_`로 시작하지 않는 것**(`Vault::is_note_file`). `_index.md`는 노트가 아니다.
- 노트가 어느 분류인지는 **어느 폴더에 있는가**로 정한다(frontmatter `type`은 그 폴더에 맞춰 다시 쓴다).
- 내장 분류 폴더 이름(`Books`·`Writing`·`Daily`·`Free`)은 바꾸지 않는다.
- 검색 색인·노트 신원 기록은 **vault 밖**(앱 데이터 폴더)에 있다 — 지워도 다시 만들어진다.

## 파일 이름

- 제목에서 `\ / : * ? " < > |`와 줄바꿈을 공백으로, 공백 여럿을 하나로, 앞뒤 공백과 끝의 `.`을 뗀다. 비면 `무제`.
  앞의 `_`도 뗀다(노트로 안 보이게 되므로).
- 같은 이름이 있으면 ` (2)`, ` (3)`…을 붙인다. 화면은 이 꼬리표를 흐리게 보여 준다.
- 일지는 `YYYY-MM-DD.md`, 분류별 제목 머릿글(예: `2026-08-11 장보기`)은 `.yamcha/templates/title-<분류>.txt`.

## 노트 한 편

```markdown
---
title: 구운몽
date: 2026-07-18
type: book
tags: [고전]
aliases: []
status: finished
author: 김만중
---

본문 (마크다운)
```

- **frontmatter**(YAML, `---`로 둘러쌈)는 늘 있다. 앱이 저장할 때 `date`(없으면 오늘)·`type`(폴더의 분류)·
  `tags`(없으면 `[]`)를 채운다. **모르는 칸은 그대로 둔다** — 다른 도구가 넣은 칸도 지워지지 않는다.
- 인코딩은 UTF-8, 앱은 줄바꿈을 LF로 쓴다(CRLF로 쓴 파일도 읽는다).
- 노트의 **날짜**(목록·통계·정렬)는 frontmatter `date`다. 앱이 만들 때 그날로 채운다. 일지는 파일명의 날짜와
  같다. 파일 수정시각은 노트 날짜가 아니다(아직 내려받지 않은 클라우드 파일의 임시 요약만 쓴다).

### 분류별 칸

공통: `date`(날짜) · `tags`(태그) · `aliases`(별칭 — 일지에는 없다)

| 분류(`type`) | 칸 |
| --- | --- |
| `daily` | (공통만) |
| `book` | `title` · `author` · `genre` · `status`(`wishlist`·`reading`·`finished`·`paused`, 기본 `wishlist`) · `isbn` · `publisher` · `cover`(`_attachments/covers/…`) · `rating`(숫자, 내 별점) · `store_rating`(숫자, 서점 평점 — 찾아 넣을 때 채운다) · `started` · `finished`(완독일) |
| `writing` | `title` · `status`(`idea`·`draft`·`revise`·`done`, 기본 `idea`) · `category` · `series` · `episode` · `goal`(목표 글자수) · `started` · `finished` |
| `free` | `title` |
| 사용자 정의 | `_types.json`의 `fields` |

### 본문의 약속

- **위키링크**: `[[제목]]` · `[[제목|보일 글]]` · `[[제목#제목줄]]` · `[[폴더/제목]]`(같은 이름이 여럿일 때). 무엇을
  가리키는지는 경로 → 제목 → 파일명 → 별칭 차례로 찾고, 앞에서 찾으면 뒤는 보지 않는다(`src/lib/resolveLink.ts`,
  `Indexer::link_names`). 제목을 바꾸면 그 노트를 가리키는 링크를 고쳐 쓴다.
- **태그**: frontmatter `tags`와 본문의 `#태그`.
- **할 일**: `- [ ] 할 것` / `- [x] 끝낸 것`. 일지는 `## 할 일` 절 안의 것만 그 일지의 할 일이다(없으면 본문 전체).
- **기록(콜아웃)**: 
  ```markdown
  > [!기록] 15:17        ← 일지: 시각
  > 내용

  > [!발췌] 2026-07-18   ← 책: 날짜
  > 내용
  ```
  종류는 기본(일지: 기록·느낌, 책: 발췌·생각·요약·질문)과 `_callouts.json`의 사용자 정의.
- **책 본문**은 두 절: `## 소개`(책 소개)와 `## 기록`(독서기록 콜아웃).
- **일지 본문**: 기본 템플릿은 `## 할 일`과 `## 기록`.

## `_types.json`

```json
[{ "id": "회의록", "label": "회의록", "folder": "회의록",
   "fields": [{ "name": "date", "label": "날짜", "kind": "date", "required": true,
                "options": [], "option_labels": [], "in_list": false }],
   "template": "", "builtin": false }]
```

- `kind`: `text` · `date` · `select`(`options`·`option_labels`) · `tags`(여러 값) · `number` · `url` · `image` · `wikilink`
- `in_list`: 목록 줄에 값을 보일지(없으면 끔). 별칭 칸(`aliases`)이 없으면 앱이 읽을 때 채운다(파일은 그대로).
- 내장 분류와 id·폴더가 겹치는 항목은 무시한다. 깨진 파일이면 사용자 분류 없이 연다.

## `.yamcha/`

| 자리 | 무엇 | 백업에 |
| --- | --- | --- |
| `format.json` | 형식의 판 | 넣음 |
| `templates/daily.md` · `free.md` · `writing.md` | 사용자가 고친 본문 템플릿 | 넣음 |
| `templates/title-<분류>.txt` | 제목 머릿글 템플릿 | 넣음 |
| `history/<경로를 펼친 이름>/<시각>.md` | 저장 직전 스냅샷(편집 기록) | 안 넣음 |
| `trash/<YYYYMMDD-HHMMSS>_<원래 이름>.md` | 휴지통. 되살리면 분류 폴더로(일지는 `Daily/YYYY/MM/`로) 간다 | 안 넣음 |
| `tmp/` | 원자적 쓰기의 임시 파일 | 안 넣음 |
| `migrate-backup/<시각>/` | 형식 이전 전에 둔 사본 | 안 넣음 |

미러는 백업과 같은 것("넣음")을 복제한다. 미러 폴더 맨 위에는 `.yamcha-mirror.json`(`vault_id`·`vault_path`)을
두어 어느 vault의 미러인지 적는다 — 다른 vault의 미러, vault 안의 폴더, vault를 품은 폴더에는 복제하지 않는다.

## 다른 편집기(옵시디언 등)와 함께 쓸 때

**고쳐도 되는 것**: 노트 본문과 frontmatter 값, 파일 이름(frontmatter에 `title`이 없는 노트는 파일 이름이 곧
제목이다 — 다른 노트의 링크는 앱이 고치지 않는다), 새 노트 만들기(분류 폴더 안에), 첨부 넣기. 앱이 바깥 변경을
알아채고 다시 읽는다.

**조심할 것**:
- 노트를 **다른 분류 폴더로 옮기면 분류가 바뀐다**(type도 따라 바뀐다).
- `title` 칸과 파일 이름이 다르면 화면에는 `title`이 보이고, 링크는 둘 다로 닿는다.
- `## 소개`·`## 기록`·`## 할 일` 제목줄을 지우거나 바꾸면 그 절을 찾지 못한다(내용은 본문에 남는다).
- 콜아웃 머리(`> [!종류] 날짜`)의 모양을 바꾸면 기록 목록·회고에서 빠진다.

**고치지 말 것**: `.yamcha/` 안(특히 `format.json`), `_types.json`의 `id`·`folder`(바꾸면 그 분류의 노트를
못 찾는다), `_index.md`(다시 만들어져 덮인다).
