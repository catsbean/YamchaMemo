# 9단계 — 링크와 정리 (0.9.0)

2026-11-12 작성. 8단계(1.0으로)는 사람 시험과 1.0.0 릴리스만 남았다. 그 사이에 실사용에서 나온 요청 셋
(링크 자동완성·없는 글 자동 만들기·여러 노트 한꺼번에 옮기기)과, 그 주변을 점검하며 찾은 것을 묶는다.

**판 번호**: 0.9.0. vault 형식은 바뀌지 않는다(새로 생기는 것은 평범한 노트와 설정 키 하나뿐) — 형식 판 번호는 그대로.

- **기록 입력창에서 화살표로 고를 수 없다 — 사용자가 짚은 자리(2026-11-12), 원인은 코드에서 확인.**
  `WikiLinkSuggest.tsx:152`가 `keyup`마다 `refresh`를 부르고, `refresh`는 늘 `setActive(0)`을 한다(`:105`).
  ↓를 누르면 keydown에서 한 칸 내려갔다가, **키에서 손을 떼는 순간 맨 위로 되돌아간다.** Esc는 같은 문제를
  `dismissed`로 막아 두었는데(`:84` 주석) 화살표는 빠졌다. 실제 앱에서 돌려 본 것은 아니다 — 9-1의 첫 일이 재현이다.
- ★ **조합 중 화살표는 `key: "Process"`로 온다**(`ime.sim.ts`가 적어 둔 WebView2의 사실). `[[역사`까지 치고 곧바로 ↓를
  누르면 그 첫 keydown은 `ArrowDown`으로 보이지 않아 IME가 먹는다 — 첫 번째 ↓가 헛돌 수 있다.
- ★ **한글 조합 중에는 편집기 목록이 따라오지 않을 수 있다.** CodeMirror 자동완성은 조합(composition) 중에는 목록을 고치지
  않고 조합이 끝난 뒤에 다시 찾는다. 한글은 마지막 글자가 늘 조합 중이라 `[[역사`를 치면 `역`까지만 걸러진 목록이 보일 수 있다.
- ★ **다크 모드에서 편집기 자동완성 창 색.** `styles.css`와 편집기 테마 어디에도 `.cm-tooltip` 규칙이 없다. 기본값은 밝은 바탕이다.
- **빠른 담기 창에는 자동완성이 없다.** `CaptureWindow.tsx`의 입력칸은 `WikiLinkSuggest`를 붙이지 않았다.
  "여기선 되고 저기선 안 된다"(WikiLinkSuggest 주석이 스스로 경계한 것)가 한 곳 남아 있다.
- **기록 입력창 목록은 8개에서 잘린다**(`MAX = 8`). 9번째 이후는 글자를 더 쳐야만 나온다.
- **없는 이름을 치면 목록이 그냥 사라진다.** 새 글을 만들 길이 그 자리에 없다.
- **편집기는 글자마다 후보를 통째로 다시 만든다**(`getLinkOptions={() => linkOptions(notes, schemas)}` — 노트마다
  `schemas.find`). 1만 편에서 얼마인지는 재 봐야 안다(짐작으로 고치지 않는다).

## 1. 정할 것 (기본값을 적어 두었다 — 다르면 시작 전에 말해 주면 된다)

1. **자동 만들기의 순간** — 기본값: **링크를 닫고(`]]`) 커서가 그 링크를 벗어났을 때**, 그리고 기록 입력창에서는 **[추가]를
   눌렀을 때**. `]]`를 치는 즉시 만들면 `[[회의]]`를 `[[회의록]]`으로 고치는 동안 `회의`·`회의ㄹ`… 이 줄줄이 생긴다.
2. **기존 스위치와의 관계** — 기본값: 스위치를 둘로 둔다.
   - 새: **"없는 글을 링크하면 자동으로 만들기"** (기본 켜짐) — 쓰는 순간, 자유노트에.
   - 기존: "없는 글을 링크하면 [만들기]" (누를 때 알림) — 그대로 두되, 만드는 곳을 **자유노트로 통일**한다
     (지금은 보고 있던 분류). 한 기능이 두 곳에 만들면 "어디 갔지"가 된다.
3. **자동으로 만든 빈 글의 뒤처리** — 기본값: 만들 때 알림에 **[되돌리기]**를 두고, 링크를 지우거나 고쳐서 아무도 가리키지 않게
   된 **빈 글(본문 없음·자동 생성 표시 있음)**은 그 자리에서 휴지통으로 보낸다. 손댄 글은 절대 건드리지 않는다.
4. **여러 개 고르기 방식** — 기본값: 목록 줄 왼쪽의 **체크 칸**(마우스를 올리면 보임) + **Shift+클릭 범위**.
   Ctrl+클릭은 이미 "새 창으로 열기"라 건드리지 않는다.
5. **1.0과의 순서** — 기본값: 0.9.0을 먼저 내고, 사람 시험은 0.9.0으로 한다(자동완성·자동 만들기는 처음 쓰는 사람의
   첫 10분에 바로 걸리는 기능이다).

9-1을 맨 앞에 두는 까닭: ②③은 새로 만드는 것이지만 ①은 **이미 있는데 불편하다고 느낀 것**이다. 원인을 모르고
②로 넘어가면 그 위에 얹는 [새 글] 줄도 같은 문제를 물려받는다.

9-5의 백엔드를 화면보다 먼저 하는 까닭: 지금 `move_note`는 한 편마다 vault 전체를 훑어 경로 링크를 고친다
(`vault.rs:798 replace_links_lenient`). 화면에서 50편을 차례로 부르면 50번 훑는다. 규칙을 모아 **한 번** 훑는
`move_notes`가 먼저 있어야 화면이 그것을 부른다.

### 9-1. 링크 자동완성 — 확인하고 구멍 메우기

**목표**: `[[`를 칠 수 있는 모든 자리에서, 한글로 쳐도, 화살표로 골라 Enter로 넣는다.

- **먼저 재현**(코드 고치기 전): 개발 빌드(testvault)에서 CDP로 한글 IME를 실제로 쳐 본다 —
  편집기 / 일지 입력창 / 독서기록 입력창 / 기록 고치기 / 빠른 담기, 라이트·다크 각각.
  `[[역사` 를 쳤을 때 목록이 글자를 따라오는지, ↑↓가 움직이는지, 조합 중 Enter가 글자를 자르지 않는지를 표로 적는다.
  짐작(§0의 ★)과 다르면 **사용자에게 어디서 안 됐는지 묻는다** — 혼자 더 파지 않는다.
- **기록 입력창 화살표 — 고침(2026-11-12, `refreshAction`·`contextKey`, 시험 6개). 실제 앱 확인은 아직.** `refresh`가 고른 자리를 무조건 0으로 돌리지 않게 한다 — 질의(`[[` 뒤 글자)가
  **바뀌었을 때만** 목록과 고른 자리를 새로 잡는다. 질의가 같으면 아무것도 하지 않는다(리렌더도 없다 — `lib/ime.ts` 규칙 2).
  이 판정을 `matches`처럼 순수 함수로 떼어 `WikiLinkSuggest.test.ts`에서 "↓ keydown → keyup 뒤에도 둘째 줄"을 못 박는다
  (DOM 시험 환경이 없으므로 `ime.sim.ts`의 가짜 입력칸으로 keydown·keyup 순서를 돌린다).
  조합 중 ↓(`Process`/229)는 `e.code === "ArrowDown"`으로도 알아보되, 조합 글자를 자르지 않는지 실제 IME로 확인한 뒤에만 넣는다.
- 한글 조합 중 목록이 안 따라오면: 편집기에 `compositionupdate`/`input`에서 `startCompletion`을 다시 부르는 확장을 붙이거나,
  안 되면 편집기도 `WikiLinkSuggest`와 같은 "직접 그리는 목록"으로 맞춘다(둘 중 무엇인지는 재현 결과로 정한다).
- 다크 모드 자동완성 창: `.cm-tooltip`·`.cm-tooltip-autocomplete`를 디자인 토큰으로 칠한다.
- 빠른 담기 창에 `WikiLinkSuggest`를 붙인다(이 창은 값을 React state로 들고 있어 IME 규칙이 다르다 — `lib/ime.ts` 규칙에
  맞게 입력칸부터 옮겨야 하는지 확인).
- 기록 입력창 목록: 8개 제한을 풀고(스크롤), 고른 줄이 화면 밖이면 따라 스크롤한다.
- 순위: 앞부터 맞는 것 → 가운데 맞는 것 순서는 그대로, **초성**(`ㅇㅅ` → 역사)도 건다 — `korean.rs`의 초성 규칙을 TS로
  옮기지 말고 5단계 검색이 쓰는 것과 같은 답이 나오는지부터 본다.
- 편집기 후보 만들기 비용을 1만 편 합성 vault에서 잰다. 16ms를 넘으면 `WikiLinkSuggest`처럼 노트가 바뀔 때만 다시 만든다.
- 게이트: 공통 + 위 재현 표를 다시 채워 전부 ○ + `WikiLinkSuggest.test.ts`에 초성·순위·8개 넘는 목록 시험 +
  `ime.sim.ts`로 조합 중 Enter 시험.
- 커밋: `9단계-1 — 링크 자동완성이 한글·다크 모드·빠른 담기에서도` (고친 것마다 따로)
- 문서: 이 문서에 재현 표와 결과, `HelpSection.tsx`의 링크 도움말.

### 9-2. 없는 글 자동 만들기

**목표**: `[[없는 이름]]`을 쓰면 자유노트에 그 글이 생긴다. 설정에서 끌 수 있고 기본은 켜짐.

- **백엔드** `ensure_link_targets(rel_path, targets: Vec<String>) -> Vec<Created>` (새 커맨드):
  - 대상마다 **백엔드가 다시 풀어 본다**(제목 → 파일명 → 별칭, `Indexer::link_names`와 같은 규칙). 화면의 판정만 믿으면
    다른 창에서 방금 만든 글과 겹쳐 둘이 생긴다.
  - 없으면 `Free/`에 만든다. 만든 뒤 그 링크로 **닿는지 확인하고 안 닿으면 별칭을 심는다** — 지금 `createMissingLink`가
    화면에서 하는 일(`회의: 3월` → 파일명 `회의 3월`)을 백엔드로 내린다. 누를 때 만들기도 이 커맨드를 쓰게 바꾼다.
  - 만든 글을 **열지 않는다**(지금 `createNote`는 만들고 곧장 연다 — 쓰던 글에서 튕겨 나가면 안 된다).
  - frontmatter에 `created_from: link` 한 줄(뒤처리가 "자동으로 만든 빈 글"을 알아보는 표시). 자유노트 템플릿은 적용하되
    제목 머릿글(날짜 등)이 붙어 링크가 안 닿는 경우는 위 별칭 절차가 맡는다.
  - **만들지 않는 것**: 빈 타깃, `/`가 든 경로 링크(`[[Books/…]]` — 폴더를 지정한 것은 오타일 때 엉뚱한 곳에 만들 수 없다),
    파일명으로 못 쓰는 것만 남는 이름, 날짜 모양(`2026-11-12` — 일지 자리다), 한 번에 20개 초과(붙여넣기 사고 — 알림으로 묻는다).
- **편집기 쪽 방아쇠**: 문서가 바뀌면 디바운스(자동저장과 같은 박자) 뒤 구문 트리에서 `WikiLink` 노드를 모아,
  **커서가 들어 있지 않은** 링크 중 못 푸는 것만 보낸다. 노트를 떠날 때·창을 닫을 때 한 번 더(커서 조건 없이).
  읽기 전용일 때·코드 블록 안의 `[[ ]]`는 보내지 않는다(구문 트리가 걸러 준다).
- **기록 입력창 쪽**: [추가]로 파일에 들어간 뒤, 그 기록의 링크를 같은 커맨드로.
- **빠른 담기·스크랩**: 담은 뒤 같은 커맨드로(본문을 긁어 온 스크랩의 `[[ ]]`는 제외 — 남의 글이다).
- **알림**: "「이름」 글을 자유노트에 만들었습니다 [열기] [되돌리기]" — 여러 개면 "3편을 만들었습니다". `MoveUndoToast`와 같은 틀.
- **뒤처리**(§1-3): `created_from: link`이고 본문이 비었고 백링크가 0이 된 글은 휴지통으로. 판정은 백엔드에서, 시험으로 못 박는다 —
  본문에 한 글자라도 있으면 남는다 / 다른 글이 가리키면 남는다 / 표시가 없으면 남는다.
- **설정**: `LinkSection`에 스위치 둘(§1-2). 저장 키 `autoCreateLinkTargets`(기본 true). 기존 `createOnMissingLink`는 그대로 읽는다.
- **자동완성과 잇기**: 맞는 후보가 없거나 정확히 같은 이름이 없으면 목록 맨 아래에 **`「이름」 새 글로`** 줄 — 고르면 `[[이름]]`이
  들어가고, 스위치가 꺼져 있어도 이 줄은 그 자리에서 만든다(사람이 고른 것이다).
- 게이트: 공통 + core 시험(이미 있으면 안 만든다 / 별칭으로 닿으면 안 만든다 / 파일명이 다듬어져도 링크가 닿는다 / 경로·날짜·빈
  이름은 건너뛴다 / 두 번 불러도 한 편 / 뒤처리 세 경우) + `invariants.rs`에 "ensure 뒤 모든 대상이 풀린다" +
  앱에서: 한글로 `[[새 이름]]` 쓰고 다음 줄로 → 자유노트에 생김·쓰던 글에 머묾, `[[회의]]`→`[[회의록]]`으로 고쳐도 `회의`가 안 남음,
  스위치 끄면 안 생김, 별도 노트 창에서도 같음.
- 커밋: `9단계-2 — 없는 글을 링크하면 자유노트에 만든다` (백엔드 / 편집기 / 입력창 / 설정을 나눠서)
- 문서: `VAULT-FORMAT.md`에 `created_from`(선택 필드, 형식 판은 그대로), `HANDOFF.md` §1 지도, 도움말.

### 9-3. `[[` 없이 쓰다가 링크 추천

**목표**: `abc`라는 글이 있을 때 본문에 `ab`·`abc`를 치면 그 글이 추천으로 뜨고, 고르면 `[[abc]]`가 된다.
**쓰던 흐름을 끊지 않는 것이 성능보다 먼저다** — `[[`는 "링크를 걸겠다"는 뜻이 분명하지만 평범한 타이핑은 아니다.

- **정한 것**(다르면 시작 전에):
  - 설정 스위치 **"글 이름을 치면 링크 추천"**, 기본 **꺼짐**. 저장 키 `suggestLinksWhileTyping`.
  - 낱말 **앞부터** 맞을 때만, **2글자 이상**부터. 가운데 맞는 것(`includes`)은 `[[` 뒤에서만.
  - 목록은 뜨되 **아무것도 골라 두지 않는다.** Enter는 그대로 줄바꿈(기록 입력창의 Ctrl+Enter도 그대로 "추가").
    **↓ 또는 Tab**을 눌러야 고르기가 시작되고, 그 뒤의 Enter가 넣기다. Esc·다른 글자를 치면 닫힌다.
  - 고르면 친 낱말을 `[[이름]]`으로 바꾼다. 이름이 겹치면 `[[폴더/이름]]`(`linkOptions`의 `insert` 그대로).
  - 띄우지 않는 자리: 이미 `[[ ]]` 안, 코드(인라인·블록), 주소(URL), frontmatter, 제목 줄(`#`), 자기 자신의 이름,
    일지(제목이 날짜다).
- **한글**: 조사가 붙는다(`abc를`). 찾을 때는 커서 앞 낱말을 그대로 쓰되, 낱말이 이름보다 길어지면(`abc를`) 닫는다 —
  조사를 떼어 다시 찾지 않는다(`autotag.rs`의 `strip_particle`을 TS로 옮기지 않는다. "정도→정" 문제를 여기까지 끌고 오지 않는다).
  여러 낱말 이름(`역사적 예수`)은 첫 낱말에서 걸리고, 띄어쓰기를 넘어 계속 치는 동안 줄의 앞부분까지 이어 붙여 맞춰 본다.
- **후보 찾기**: 이름을 소문자로 정렬해 두고(노트가 바뀔 때만 다시) 이분 탐색으로 앞글자 범위를 집는다. 글자마다 전체를 훑지 않는다.
- **구현 자리**: 편집기는 9-1에서 정한 방식(CodeMirror 자동완성 source를 하나 더 / 직접 그리는 목록) 그대로에 방아쇠만 추가,
  기록 입력창은 `WikiLinkSuggest`에 "낱말 방아쇠"를 더한다 — `refreshAction`·`contextKey`를 그대로 쓴다.
  "골라 두지 않음"(active = -1) 상태가 두 곳 모두에 새로 생긴다.
- **재고 나서 판단**: 1만 편 합성 vault에서 글자 하나당 후보 찾기 시간을 잰다(예상 1ms 안팎 — 짐작이다).
  16ms를 넘으면 기본 꺼짐을 유지하는 것으로는 모자라니 방식을 다시 본다. 기록 입력창에서는 평범한 타이핑 중 리렌더가
  0인지도 센다(`lib/ime.ts` 규칙 2 — 목록이 뜰 때만 그려야 한다).
- 게이트: 공통 + 시험(앞글자만 / 2글자 문턱 / 코드·주소·링크 안에서는 안 뜸 / 골라 두지 않았을 때 Enter는 줄바꿈 /
  ↓ 뒤 Enter는 넣기 / 겹치는 이름은 경로로) + `ime.sim.ts`로 조합 중 Enter·Tab + 실제 IME로 편집기·기록 입력창에서
  한글 이름 쳐 보기 + 실측 수치를 이 문서에.
- 커밋: `9단계-3 — 글 이름을 치면 링크 추천 (기본 꺼짐)` (찾기 / 편집기 / 입력창 / 설정을 나눠서)
- 문서: 도움말, `HANDOFF.md` §1 지도, 이 문서에 실측.

### 9-4. 없는 링크가 눈에 보이게

**목표**: 가리키는 글이 없는 링크는 누르기 전에 알 수 있다. (자동 만들기를 끈 사람, 경로 링크, 예전에 쓴 링크)

- 편집기(`livePreview.ts`)·읽기 화면(`NoteText.tsx`)에서 못 푸는 `[[링크]]`를 흐린 색 + 점선 밑줄로.
  판정은 `resolveLink`(이미 화면에 있는 `notes`로) — 백엔드를 부르지 않는다.
- 점검 화면(`audit.rs`)에 **"가리키는 글이 없는 링크"** 항목. 지금 점검은 별칭 충돌만 본다. 고치기는 [만들기](9-2의 커맨드) 하나뿐,
  자동 수정은 없다(audit의 원칙).
- 1만 편에서 편집기 장식 비용을 잰다 — 보이는 범위의 링크만 푼다.
- 게이트: 공통 + `NoteText.test.ts` + audit 시험 + 앱에서 글을 지우면 그 글을 가리키던 링크가 곧 흐려지는지.
- 커밋: `9단계-4 — 가리키는 글이 없는 링크를 흐리게`
- 문서: 도움말, 이 문서.

### 9-5. 여러 노트 고르기 → 이동

**목표**: 목록에서 여러 편을 골라 한 번에 다른 분류로 옮기고, 한 번에 되돌린다.

- **백엔드** `move_notes(rel_paths, new_type_id) -> { moved: Vec<(from, to)>, skipped: Vec<(rel, 까닭)> }`:
  - 파일은 한 편씩 옮기되(`relocate_file` — 반쯤 실패하지 않는 기존 절차 그대로) **링크 고치기는 규칙을 모아 한 번만** 훑는다.
  - 한 편이 실패해도 나머지는 계속하고, 못 옮긴 것은 까닭과 함께 돌려준다(책·일지, 이미 그 분류, 파일 잠김).
  - 진행은 기존 `relocate-progress`로(옮기기 n/전체 → 링크 → 색인). 색인 따라잡기도 한 번에.
  - 기존 `move_note`는 이것을 한 편으로 부르는 얇은 껍데기로 남긴다(되돌리기·우클릭이 쓴다).
- **화면 — 고르기** (`Dashboard.tsx`의 `ListDashboard`부터, 그다음 홈·글쓰기·할 일 화면의 노트 목록):
  - 줄 왼쪽 체크 칸(마우스를 올리거나 하나라도 골랐으면 보임), Shift+클릭 범위, 묶음 머리글의 "이 묶음 전부", `Esc`로 풀기.
  - 고른 상태는 `lib/selection.ts` 훅 하나로(rel_path 집합 + 마지막 고른 자리). 분류·필터·정렬이 바뀌면 푼다 —
    안 보이는 줄이 골라진 채 옮겨지면 안 된다. `useIncremental`로 아직 안 그린 줄은 Shift 범위에는 들어가되 "N개"에 정확히 센다.
  - 열려 있는 글이 고른 것에 들어 있으면 먼저 저장한다(지금 `moveNoteTo`가 `moveCurrent`로 돌리는 것과 같은 까닭).
- **화면 — 하기**: 하나라도 고르면 목록 위에 띠 — `3개 고름 · [이동 ▾] · [풀기]`. 우클릭 메뉴도 고른 것이 있으면 "3개를 …로 이동".
- **되돌리기**: `moveUndo`를 여러 편으로 넓힌다 — "3편을 글쓰기로 옮겼습니다 [되돌리기]", 파일명이 바뀐 것은 몇 편인지 알린다.
  못 옮긴 것이 있으면 같은 알림에 "2편은 옮기지 못했습니다 [보기]".
- 게이트: 공통 + core 시험(링크 훑기가 한 번 / 중간 실패 뒤 나머지 진행 / 이름 겹침 `(2)` / 경로 링크가 전부 따라옴 /
  되돌리면 처음과 같음) + proptest 불변식에 일괄 이동 추가 + 1만 편 합성 vault에서 100편 이동 시간(한 편씩 100번과 비교해 적는다) +
  앱에서 Shift 범위·필터 바꾸면 풀림·열린 글 포함·다른 창에 반영.
- 커밋: `9단계-5 — 여러 노트를 한 번에 옮긴다` (백엔드 / 고르기 / 띠·되돌리기를 나눠서)
- 문서: `HANDOFF.md` §1 지도·§2.3 바인딩, 도움말, 이 문서에 실측.

### 9-6. 고른 노트에 할 수 있는 다른 일

**목표**: 9-5의 고르기를 삭제와 태그에도 쓴다. 지금 삭제는 **글을 열어야만** 된다(`deleteCurrent`뿐, 목록 우클릭에 없다).

- 목록 우클릭에 **[휴지통으로]** (한 편). 삭제 확인 설정(`DeleteConfirmSection`)을 그대로 따른다.
- 고른 것 띠에 `[휴지통으로]`·`[태그 붙이기]`. 삭제는 "5편을 휴지통으로 보냈습니다 [되돌리기]"(휴지통 복원을 부른다).
- 백엔드는 `delete_notes`·`add_tag_to_notes` — 색인 커밋을 한 번만.
- 책·일지도 삭제는 된다(이동과 달리). 책을 지우면 독서기록이 딸려 있다는 것은 지금 한 편 삭제와 같은 문구로 알린다.
- 게이트: 공통 + 시험 + 앱에서 되돌리기까지.
- 커밋: `9단계-6 — 목록에서 지우기·태그, 여러 편 한꺼번에`
- 문서: 도움말.

## 4. 이번에 하지 않는 것 (찾았지만 미룬다)

- **`[[글#제목]]`으로 그 자리까지 가기·`#` 자동완성** — 지금은 `#` 뒤를 버리고 글만 연다. 값은 있지만 요청 셋과 독립이다.
- **`[[글|표시]]`의 표시 이름 자동완성**, 링크 위에 마우스를 올리면 미리보기.
- **끌어다 놓기로 이동**(목록 → 왼쪽 메뉴). 체크 칸 + 띠로 충분한지 써 보고 정한다.
- **하위 폴더.** 이동은 "분류 바꾸기"다. 분류 안의 폴더는 vault 형식을 건드린다 — 1.0 뒤.
